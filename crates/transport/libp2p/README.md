# libp2p

Concrete rust-libp2p Swarm backend: Noise, GossipSub, direct v2, endpoint directory, connection/dial admission, AutoNAT v2, Relay v2, DCUtR, Identify and Kademlia driver. **That is the target, not an inventory** — the status below says what is built.

**Current status:** Stage 11, active workspace member. This paragraph said "Stage 5" from Stage 6 until now, which is the drift a status line is most prone to: nothing compiles it, and each stage that lands a behaviour is looking at the behaviour.

What is here: TCP, Noise, Yamux and Identify from Stage 4; direct v2 over request-response from Stage 6; signed GossipSub from Stage 7; the endpoint directory from Stage 8; the Kademlia driver from Stage 10; and, from Stage 11, the AutoNAT v2 client and server, the Circuit Relay v2 client (with the relay transport beside it) and server, relayed peer paths, DCUtR under its attempt lifecycle, path preference with the stability gate and the head-start, and the runtime's own network-change detection — the behaviours each behind a `SubstrateConfig` field that is `None` by default, so a default profile constructs none of them. Under all of it sits the admission funnel Stage 5 required before any autonomous behaviour existed — every outbound dial reachable only through a ticket the root `ConnectionManager` issues, every inbound connection passing pre-Noise admission before its handshake begins, and every peer classified from the profile's trust sources rather than assumed, including inbound, which is closed if the current policy does not retain it, and on revocation, which evicts the connections it withdraws.

`autonat`, `relay` and `dcutr` are compiled as of Stage 11's features-on step, and every behaviour they carry has since been given a field, a constructor and a switch (steps 3 to 8), off by default: what keeps a default profile from running one is the `None`, not the feature list.

Each of those was **absent from the `libp2p` feature list** rather than merely unused until the stage that earned it, because a behaviour that is compiled in is one that can be switched on before its admission policy exists. Stage 11 spent the last three entries, so no behaviour this stage builds is withheld there any more and the guarantee rests on the outbound gate, the trust classification and their tests. **`mdns` and `dns` joined the list on 2026-09-20, and neither dials on its own.** `mdns` had been held off first by RUSTSEC-2026-0118 and -0119 inside the `libp2p-mdns 0.48` line `libp2p 0.56` pinned, then, once PR #109's bump to `libp2p 0.57` cleared those, only by a stage decision nobody had taken. The multicast mechanism is now built: `MdnsScope` swallows the crate's address injections, because a discovery provider never writes the address book (ADR-0011), and the driver applies ADR-0052's address-class boundary where a candidate is learned. It is constructed only when `SubstrateConfig::mdns` is `Some`, which nothing does before Stage 12 composes providers, and Stage 11's `mdns` deadline reads TAKEN-NOT-MET until SPIKE-010's multicast run. Real multicast packets do cross the crate in `tests/mdns_bounds.rs`, inside a network namespace on a dummy interface, where ADR-0053's bounds on the vendored `libp2p-mdns` are asserted; the deadline's LAN rows (two nodes on a carrying and a blocking domain) have not run. `dns` is built too: the Swarm builder wraps the base transport in it, so a `/dns4` or `/dns6` name the **operator** configures resolves at dial and `profile-config` accepts one. A name a **peer** supplies is refused where it would enter the address book or Kademlia's routing table (ADR-0052, A 2026-09-20), because to a peer the resolver is an oracle. Before the transport was built, such a name was undialable only by accident — it failed `MultiaddrNotSupported` and was evicted as structural — which is why that refusal is now a rule with a hook rather than a property of the transport list. See the plan's Stage 11 section for what that does and does not mean before Stage 12 composes providers. (The endpoint directory was never on that list — it rides on the `request-response` feature direct v2 already brought in, so what withheld it was having no code, until Stage 8 wrote it. It is advertised today, which the protocol-set test asserts.)
