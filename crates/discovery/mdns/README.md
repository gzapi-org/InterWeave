# mdns

MdnsDiscovery implementation.

**Current status:** Stage 9, active workspace member. The normalization half of LAN discovery: raw `(peer, address)` observations pushed in by the backend become bounded, validated candidates. **This crate owns no socket** — the multicast mechanism is a libp2p behaviour in `crates/transport/libp2p`, because only that crate may own a Swarm.

Any host on the multicast domain can advertise, so mDNS grants **zero trust** and every bound is applied before an observation is emitted. A peer string outside the identity grammar is dropped, not repaired. A network that blocks multicast makes this provider *degraded*, never fatal, and leaves the other providers untouched.

**The multicast backend is deferred, and what defers it is the multicast mechanism Stage 9 never built — a stage decision.** It was a dependency advisory until the `libp2p 0.57` bump, and that history is kept below because the retired blocker is the one a reader remembers. Enabling libp2p's `mdns` feature USED TO pull `hickory-proto 0.25.x` with RUSTSEC-2026-0118 (the advisory says "no safe upgrade", which is about the 0.25 line it names — 0.26.1 carries the fix) and RUSTSEC-2026-0119, which `tools/checks/check_dependencies.sh` refuses. This crate is complete without it — observations arrive through `push_discovered`/`push_expired`, which is how they were always going to be tested — and the socket lands with the libp2p major bump that moves `libp2p-mdns` onto `hickory-proto` 0.26 — available since `libp2p 0.57`, whose `libp2p-mdns 0.49` clears both advisories (measured 2026-09-19), and costed in the plan's Stage 9 record; what is left is the decision to take that bump, not a fix to wait for. Until then a profile that sets `enabled: true` on an `mdns` provider is **refused at validation**, the same way an enabled `kademlia` entry is: a provider that configuration enables but the build omits must fail loudly rather than start healthy and discover nothing (`architecture/discovery/PROVIDER-CONTRACT.md`). That refusal lifts in the change that wires the socket.  **That is no longer what defers it (2026-09-19).** The `libp2p 0.57` bump moved the graph to `libp2p-mdns 0.49` on `hickory-proto 0.26.3` and the advisory check is clean, so what remains is the multicast mechanism Stage 9 never built — a stage decision, not a dependency one.
