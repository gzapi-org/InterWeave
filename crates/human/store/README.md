# store

SQLite implementation of pending_outbound, unread_inbound, kept_inbound, contacts/preferences; deliberately no general durable history API.

**Current status:** Stage 3, active workspace member. The three ADR-0044 states as its only content: pending outbound, unread inbound, and inbound the receiver explicitly kept. Beside them, content-free metadata that cannot reconstruct a deleted body: `settings`, and since schema v5 `contacts`, `contact_routes` and `conversation_index`, each checked column by column. Since v6 each pending row also carries the transport `MessageId` its first send minted and every retry reuses, so a retry after restart is deduplicated by the receiver. Since v7, `read_pairs` records each message read and not kept by its origin and application id alone: a later copy is refused as `AlreadyRead`, a duplicate, so a message read before a restart is not unread again. At most `READ_PAIR_CAP` (4096) pairs are held, the oldest evicted in the transaction that records the newest (STATE.md; architect-cto's Q5 ruling). `unkeep` returns the session copy for a re-keep (Q6) and records a pair too. `verify_shape` refuses any other table, view, or trigger on every open, so the absence of a general history API is enforced rather than merely intended.
