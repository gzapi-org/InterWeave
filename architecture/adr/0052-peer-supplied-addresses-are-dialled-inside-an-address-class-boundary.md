# Peer-supplied addresses are dialled inside an address-class boundary

**Status:** Accepted

## Context

Two protocols in the v1 substrate make this node open a socket to an address another peer chose. The AutoNAT v2 server role (ADR-0035; `architecture/transport/libp2p/AUTONAT.md` §7) dials back a candidate the probing client named. DCUtR (ADR-0035; `architecture/transport/libp2p/DCUTR.md` §6) dials, during a hole punch, whatever multiaddrs the far end's CONNECT message lists — `libp2p-dcutr` 0.14.1 passes them through unchanged at both of its dial sites. Both peers are admitted by the class gate: the probing client by the infrastructure service policy (ADR-0036), the punch partner by data-plane trust (ADR-0012). Neither trust is trust with where this host opens sockets: a loopback, link-local, or private candidate turns the node into a probe of its own host, its cloud metadata endpoint, or its LAN, and the runtime cannot tell that dial from a legitimate one by its origin alone.

`AUTONAT.md` §7 already draws the line for the dial-back — a literal-IP, source-equality and address-class rule, enforced by `ProbeServer` at its pending outbound hook before any socket, with `is_probeable_address` (`crates/transport/runtime/src/reachability.rs`) as the shared predicate. `DCUTR.md` §6 stated no rule for the candidates a punch dials; PR #102's blind review named the gap and p2p-network-dev handed it up on 2026-09-18 as a contract decision. Each protocol had been deciding its own boundary, or none, at the point its hook was written. The rule is cross-cutting, so it needs a record the next peer-supplied dial reads before it has a hook.

A third path was inside rule 1 from the day it was written and had never been read as such (A 2026-09-20): the addresses a peer asserts about ITSELF in Identify's `listen_addrs`, which the runtime learns into the address book (`crates/transport/libp2p/src/runtime/dialing.rs`, the Identify arm, through `learn_route` into `ConnectionManager::learn_address`) and which the retry scheduler then dials. That path checked only that the peer was classified and capped the count; it had no class predicate. Building the DNS transport (Stage 11's fifth obligation, PR #111) made the gap visible, because a `/dns4` listen_addr that had failed `MultiaddrNotSupported` by accident now resolves — a classified peer could make this node query a name of its choosing and connect to whatever it resolved to — and the record's own revisit clause said to reopen it when a name the runtime must resolve arrived. p2p-network-dev raised it on 2026-09-20 and stopped at the diagnosis; this amendment is the answer.

## Decision

1. **Every address this runtime dials because a peer supplied it sits inside an address-class boundary, enforced before any socket.** A peer's authorization (ADR-0012, ADR-0036) decides whether its request is heard; the boundary decides where this host may connect on its behalf. The two are separate gates and neither substitutes for the other.
2. **The boundary's common floor**, for every instance: the candidate is a literal IP multiaddr — **no DNS name from a peer** (A 2026-09-20: the resolver policy is that a name is resolved only when the OPERATOR supplied it — profile configuration's static bootstrap peers, `static_servers` and `static_relays`, and the operator's `AddAddress` command (`SwarmCommand::AddAddress`, the runtime's one operator door for an address; the record named a `LearnAddress` command that never existed — corrected A 2026-09-25) — because to a peer the resolver is an oracle and to the operator it is their own configuration; the DNS transport exists for the operator's names (ADR-0010) and a peer-supplied name is refused at the boundary whatever the peer's trust, so the refusal of a peer's name is the boundary's rule and never an accident of which transports the Swarm was built with), no `p2p-circuit` component (a relayed address tests the relay, not the peer); loopback, unspecified, multicast, link-local and the other special-use ranges are refused whoever supplies them. Global unicast addresses are admitted.
3. **Private ranges (RFC 1918 IPv4, IPv6 ULA) are decided per instance**, because the instances differ in what a private candidate can legitimately mean. The dial-back (`AUTONAT.md` §7) refuses them: an Internet reachability verdict about a private address is meaningless, and the requester's observed source is global by construction. The hole punch (`DCUTR.md` §6) admits a private candidate only when this node itself holds a non-loopback listener in a private range of the same family: a LAN punch is the legitimate case and both ends of one sit on private networks, while a host with only global listeners has no LAN to punch across and a private candidate handed to it is exactly the internal-network probe the floor exists to refuse.
4. **Source-equality is the dial-back's clause alone.** A dial-back verifies the address the request arrived from, so the candidate IP must equal the observed source; a punch candidate legitimately differs from the relayed connection's observed address — that is what NAT means — so §6 carries no such clause and says so.
5. **Enforcement is the ProbeServer shape at every instance: filter what is dialled, refuse only when nothing survives, and never let a refused address reach a socket.** The crate's dial list is not readable outside the Swarm crate until the pending outbound hook hands it over, and the hook can add addresses but not remove one — so the filter runs there by deny-and-reissue: a crate dial carrying a refused candidate is denied at the hook, before any socket, and the wrapper reissues the survivors as its own dial with the crate's other options kept (the peer, the dial condition, the initiator's role override); each removed candidate is counted by class (`candidates_removed`), an attempt with no survivor ends by class (`refused_by_class`), and the same hook judges the wrapper's reissued dial as the backstop (`backstop_refusals`, a distinct label: a refused address reaching it there is a defect in the layer before). The class is named in the diagnostic and the address never in a log. What this node learns and offers is held inside the boundary too, so its own CONNECT never carries a refused address. The pinned crates implement none of it; the wrappers do. (Corrected three times on 2026-09-18 from the reviews of PR #102: the hook cannot filter; a whole-list verdict at the hook, composed with a private listener legitimately offered beside a global mapping, refused every punch from a home-NAT node toward a global-only far end; and the Dial is not readable before the hook, so deny-and-reissue is the site.) **The clause above is about the EXPLICIT list a dial carries. A dial that EXTENDS its addresses through the behaviours** (A 2026-09-25) — Kademlia's walk, the relay client's reservation dial, any `DialOpts::peer_id(p).build()` — carries no explicit list, and what it dials is the union the ROOT behaviour's pending-outbound hook returns: the Swarm calls that hook once, on the type it was built with, and extends the dial from that one return (libp2p-swarm 0.48.0 `Swarm::dial`, read 2026-09-25 — `Ok(addresses)` is appended when `extend_addresses_through_behaviour` is set, `Err` is `DialError::Denied`). So the funnel for behaviour-contributed addresses is a wrapper AROUND the composed behaviour — not a sibling field, which sees only the explicit list and decides the address at the established hook, after the socket (`outbound_gate.rs` F9) — pruning the union by class before it returns it, counting each removed address by class (`candidates_removed`), never logging one, and denying only when it REMOVED at least one address, nothing survived, and the dial carried no explicit address — a dial to which no behaviour contributed anything passes through empty, the Swarm's own `NoAddresses`, because the funnel did not cause that emptiness and a refusal count must count refusals the funnel made; the denial itself is counted (`dials_denied`), because the Swarm discards the denial of a behaviour-originated dial and the count is the only place it is visible (SPIKE-004). Deny-and-reissue remains the shape for the explicit list at the sites that own it, and the root is the backstop for an explicit refused address as before. One funnel, because the blind re-review of PR #111 found five paths behaviour-contributed addresses take to a socket after two learn sites had been hooked: a boundary enforced one dial site at a time is closed only where someone has looked.
6. **One predicate family, one test that binds it.** `is_probeable_address` is the dial-back's predicate; the punch's is its sibling in the same module, taking this node's listener set for rule 3. A test asserts that every address the dial-back refuses on class the punch refuses too — the floor is a subset relation, checked, so the two lists cannot drift apart silently.
7. **No test-only knob admits a refused class.** The substrate demonstrates a refused candidate as REFUSED, not a connection MADE; a test that needs the connection runs at the crate level with the bare behaviour, or over a private-range pair under rule 3. A knob that admits loopback in a profile is the hole this decision closes, and SPIKE-004's split (crate-level on loopback, substrate-level refusing it) is the precedent.
8. **Every path by which a peer-supplied address enters a STORE or a DIAL is an instance, and reads this record first** (A 2026-09-20, when the rule widened from a new dial to every path that enters the book; restated A 2026-09-25 in two halves). **Stores** — the address book, Kademlia's routing table and the offer stash ahead of it, PeerCache re-entry, the AutoNAT learned-server list, the relay reservation list, and the next one — hook at the LEARN site: a refused address never enters the store, is counted by class and is never logged, because a stored address is later dialled, offered in a CONNECT or handed to a consumer, so the store must be clean whatever the dial path does (mDNS's shape, `providers/mdns.md` §Address class). **Dials** reach a socket by one of two routes, and the instance statement says which. An address a behaviour CONTRIBUTES — the extension — is enforced once, at the root funnel of rule 5, and nowhere else; a class predicate at such a dial site is a diagnostic refinement, never the enforcement. An address a dial carries EXPLICITLY is the caller's, and the funnel passes it untouched (rule 5); for a store whose contents are dialled explicitly — the AutoNAT learned-server list, dialled address by address through the runtime's own dial; the relay reservation list, whose picked address is the explicit part of the relay client's dial — the learn-site hook IS the enforcement, and its absence is a socket exposure with the funnel standing (corrected 2026-09-25, on p2p-network-dev's reading of the two call chains). Each instance states its rules 3 and 4 in the document that owns the path, citing this ADR, before its hook is written. The instances as of 2026-09-25. Stores hooked: the address book at Identify's learn site (ADR-0011 §Identify's advertised addresses; PR #111 — the floor, rule 3 admitting a private range while this node holds a non-loopback listener of the same family, no rule-4 clause since a listen_addr legitimately differs from the observed remote under NAT); Kademlia's offer stash, through which Identify `listen_addrs` and every `OfferRoutingPeer` — a query result, a PeerCache hint on re-entry — reach `add_address` (`kademlia-integration.md` §7, `providers/kademlia.md` §Routing eligibility, `providers/peer-cache.md` §Ownership; PR #111 commit 66e5663, the book's predicate at the second door); mDNS at its learn site. Dials on the explicit list, under rule 5's deny-and-reissue at their own sites: the AutoNAT dial-back (`AUTONAT.md` §7) and the DCUtR punch (`DCUTR.md` §6). Behaviour-extended dials: the root funnel — `RootFunnel<B>`, wrapping the whole composite in every Swarm the runtime builds (PR #111 commits eefacd4 and 61c89bc; the measurement is `tests/root_funnel.rs`). Landed on the same PR on 2026-09-25, after the owner held it for this closure rather than land the two stores alone: the AutoNAT learned-server list and the relay reservation list hooked at their learn sites (03e5b11 — the only enforcement for a store dialled explicitly); Kademlia query-result candidates leaving the driver inside the boundary (20fe4b7, hygiene); Identify's crate-level address cache disabled (a02c14d) — the runtime's book is the only address store the runtime WRITES from Identify, the crates' own stores being named with their doors in ADR-0011 §Identify's advertised addresses; every store's refusal count readable on the one runtime handle (f7baced); and the boundary's wiring proven on a running node, the funnel's by its type (b11f850). What stays raw by decision: `SwarmEvent::Identified.listen_addresses`, the consumer's own evidence of what a peer said — the last sentence of this rule names what a consumer must not do with it. The plan's §15 precondition reads MET on that head. No production composer of the runtime exists before Stage 12 — the runtime's own `start` builds Kademlia and the AutoNAT client whenever its config enables them — so until Stage 12 composes one the boundary is proven on test topologies, and every test or spike that enables those behaviours exercises the hooked paths. Operator-supplied inputs — profile configuration and the operator's `AddAddress` command — are outside the boundary, because no peer chose them; a discovery candidate is never an operator input and never enters through that command (Stage 12's composition rule, plan §15).
9. **Provenance is a property of the door, never a tag on the address** (A 2026-09-25). Two doors admit an address into this runtime: the operator's — profile configuration and the operator's `AddAddress` command — and the peer's, everything a behaviour learns or a peer asserts. The runtime keeps ONE record of what entered by the operator door, the operator set, held as a shared handle beside the class-policy handle; an address in that set is admitted at every store door and at the root funnel whatever its class — the operator's `/dns4` bootstrap seed resolves, the operator's LAN seed routes — and every other address meets the floor. No carrier gains a provenance field (`OfferRoutingPeer`, `AddAddress` and `CandidatePeer` stay as they are): a field a peer's path could set is a field a peer's path will set, and the door is what a peer cannot choose. This is how the routing door admits an operator's named seed — `admits_offer` consults the operator set — and it corrects a defect recorded on 2026-09-25: the static-bootstrap provider's candidates reach that door as `OfferRoutingPeer` carrying peer and addresses only, and the floor as first built refused the operator's own `/dns4` seed, fail-closed and unreachable before Stage 12. The set is seeded at start from the profile — `SubstrateConfig.operator_addresses`, which the composition root fills from the static bootstrap, static server and static relay blocks (PR #111 commits 56c4e56, 748ce6a) — and by the operator's `AddAddress` command thereafter; `validate` refuses an entry that does not parse and more entries than the set holds, rather than seeding part of it, and an operator address refused at the set's bound is readable through the runtime (0bf8886). What the runtime does NOT yet have is a peer-door API for a Stage 12 composer to hand discovery output to the address book: `add_address` is the operator door, and the discovery-conformance composition test that pipes `DiscoveryManager` candidates into it is a test topology using the only door there is — named as such there, and not a pattern Stage 12 may copy. The in-boundary learn command is a Stage 12 obligation (plan §15), p2p-network-dev's; the conformance test converts to it when it exists.

## Alternatives considered

Trust in the far end as the whole boundary — a data-plane-trusted peer may name any address — was the state of `DCUTR.md` §6 and was rejected: trust classes authorize protocols, not sockets, and a compromised or merely careless trusted peer would turn every node it reaches into a scanner of that node's own network. Refusing private ranges everywhere, as §7 does, was rejected for the punch because it removes the LAN case, which is the one where a punch helps a pair of peers the most. Admitting private ranges everywhere was rejected because a global-only host has nothing to gain from a private candidate and everything to leak. Keying the punch's admission on the candidate sharing a subnet with one of this node's listeners was considered and declined for now: it is stronger but needs the interface's prefix, which the listener set does not carry; rule 3's family-and-range condition is the checkable half and the revisit condition names the stronger one. A profile knob admitting loopback for tests was rejected under rule 7.

## Consequences

`DCUTR.md` §6 gains the rule; `AUTONAT.md` §7 is unchanged in substance and now cites this record as its principle. `CONNECTIVITY.md` §13's eligibility sentence gains the class rule beside the gate. A hole punch toward a peer whose candidates are ALL refused fails as any other failed attempt (a list mixing admitted and refused candidates loses only the refused ones), enters the peer's cooldown, and is visible by class in `dcutr_attempts_total{outcome}`. A LAN punch between two private-network peers keeps working; a punch from a global-only host to a private candidate is refused, which is the intended loss. The loopback wire test in PR #102 moves as rule 7 says. Every future protocol that dials a peer-named address inherits one extra paragraph of contract before its hook.

## Security implications

The invariant: a peer's request never chooses a socket outside the class boundary, whatever the peer's trust. Under it an attacker holding a trusted PeerId cannot use this node to probe its loopback services, its cloud metadata endpoint (link-local), or — on a global-only host — its private network. Residual risk accepted: on a host that does hold a private listener, a trusted peer can make it attempt one authenticated libp2p connection to a private address in the same range; the attempt carries a Noise handshake, so a non-libp2p service sees a failed handshake and the far end learns nothing the punch outcome does not already tell it. The subset test (rule 6) and the pending-hook locus (rule 5) are what keep the boundary from decaying into prose.

## Operational implications

Nothing to configure: the boundary has no knob (rule 7). An operator sees refusals by class in the instance's attempt counter and in the diagnostic's named class, never the address. A host whose punches toward LAN peers fail with `refused_by_class` is a host with no private listener — which is a fact about its listener configuration, not a defect in the peer.

## Implementation implications

`crates/transport/runtime/src/reachability.rs` gains the punch predicate beside `is_probeable_address` and the subset test; `crates/transport/libp2p/src/hole_punch.rs` (`HolePunchScope`, PR #102) enforces it at its three sites — the candidates the Swarm reports, the listeners it offers, and the pending hook of every punch dial, where a crate dial carrying a refused candidate is denied and the survivors reissued as the wrapper's own — the hook judging that reissued dial as the backstop — and counts it; `DCUTR.md` §6, `CONNECTIVITY.md` §13 and `AUTONAT.md` §7 carry the text. All on PR #102, where the dial site is — the rule and the hook land together (ADR-0046: DCUtR is stage 11 step 8, so nothing here is inert). p2p-network-dev owns the range; this record is the caller. The Identify instance (A 2026-09-20) lands on PR #111 beside the DNS transport that exposed it — rule and hook together, as on #102: a class predicate at the Identify learn site in `dialing.rs`, a sibling of `is_discovered_address` in `reachability.rs` under rule 6's subset test, and the instance stated in ADR-0011 §Implementation implications. The root funnel and the operator set (A 2026-09-25) landed on PR #111 too, the owner having held it for the full closure: p2p-network-dev's code, in this order — Identify's cache disabled with a test that fails if it returns (a02c14d); the measurement, committed as a test (the test is the record, below): a Kademlia dial extending through the behaviours toward a peer whose in-query addresses hold a loopback and a `/dns4` name opens no socket with the wrapper and does with it removed, the control that proves the measurement live; then the wrapper around the composed behaviour (eefacd4, 61c89bc); then the operator set, seeded from the profile, consulted at every store door and the root (56c4e56, 748ce6a). Measured 2026-09-25 on PR #111 (`crates/transport/libp2p/tests/root_funnel.rs`, three tests on real sockets with a raw TCP listener on loopback standing where the peer-supplied address points: control — an unwrapped Kademlia walk dials the loopback address in its table and the socket opens; funnel — the same walk wrapped opens no socket, the loopback removed as special-use and a `/dns4` beside it as not literal, the counters moving in that same run, so the absence is not a walk that never started; explicit — a dial carrying its own loopback address passes untouched; mutation — an unpruned pass-through fails the socket assertion): the union reaches the outer wrapper and the deny-at-root fallback is not needed. The test is the record: a crate test re-measures on every CI run of every pull request, which is stronger than a one-time log, and `SPIKES.md`'s committed-log rule binds a pinned spike, which this is not. The remaining store hooks landed on the same PR — the AutoNAT learned-server list and the relay reservation list (03e5b11) because their contents are dialled explicitly and the hook is their only enforcement, the Kademlia query-result candidates (20fe4b7) as store hygiene — each through the operator set's predicate (floor, rule 3, operator door), refusals counted by class on the one readable handle (f7baced), with tests and controls. `SwarmEvent::Identified.listen_addresses` stays raw: it is the consumer's own evidence of what a peer said, not a store the runtime dials, and filtering it would hide the evidence — a consumer that feeds it back through the operator's `AddAddress` command is laundering a peer's address, which rule 8's last sentence forbids. Rule 8's instance list is updated by the change that makes each line true, not before.

## Revisit conditions

Reopen rule 3 if the listener set gains the interface prefix, at which point the subnet-match condition replaces family-and-range. Rule 3 carries one measured consequence to keep in view: the crate's protocol refuses an empty candidate list on either side (`NoAddresses`), so a profile with only loopback listeners cannot complete a CONNECT at all under rule 2 — a test topology, never a production one under ADR-0035, and the loopback-refused wire test gives its subject a private listener for exactly that reason. Reopen rule 2 if a deployment needs a punch across link-local (IPv6 link-local peers on one segment), which today is refused with the rest of the floor. The record was reopened once on that condition (2026-09-20, the DNS transport): rule 2's first clause is now the resolver policy — operator names resolve, peer names are refused — and the paths that enter the book are instances under rule 8. Reopen rule 2 again only if a protocol arrives whose PEER-supplied address must be a name by design (a rendezvous by hostname, say), which would need a per-instance resolver policy stated in that protocol's document, never a relaxation of the floor. Reopen rule 5's root clause if a `libp2p-swarm` bump changes how `Swarm::dial` consults the behaviour — a per-field hook, or an extension the root cannot see: the measurement that rule 5's implementation clause names is the tripwire, and it runs again at every bump of that crate.
