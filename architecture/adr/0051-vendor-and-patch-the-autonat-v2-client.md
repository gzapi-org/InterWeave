# Vendor libp2p-autonat and give its v2 client a re-test entry point

**Status:** Accepted

## Context

ADR-0035 labels a direct address `verified_public` only on fresh evidence from **multiple distinct authorized AutoNAT v2 servers**, and states why: "reducing dependence on one lying/misconfigured observer". `architecture/transport/libp2p/AUTONAT.md` §5 adds that a verified state "must not survive beyond its evidence TTL without refresh". Both are accepted, both are security or liveness properties rather than tunings, and the standard-v1 client cannot deliver either.

The reason is the candidate lifecycle in `libp2p-autonat` 0.15.0's v2 client, measured on 2026-09-09 by reading the crate rather than its documentation. Its tick sweeps only candidates whose status is `Untested` (`v2/client/behaviour.rs:319-321`). Issuing a probe sets `Pending` and asks one randomly chosen dialled server (`:297-300`, `:340`). A received dial-back sets `Received` (`:166`); a server's "not reachable" sets `Failed` (`:232`). Only `UnsupportedProtocol` and `Io` go back to `Untested` (`:212`, `:223`). Re-reporting an address only raises its score — the entry is never removed and its status never changes (`:108-112`). Two paths also leave a candidate `Pending` for ever with no event: a server reporting success when no dial-back arrived (`:186-198`), and a request dropped because the handler's ten-slot request map was full (`v2/client/handler/dial_request.rs:99-113`) — after the status was already set. The one public mutator, `validate_addr`, is `#[doc(hidden)]` and only *sets* `Received` (`:364`). **Once an address has been tested, no public path tests it again.** So an address is probed at most once, by one server, for the life of the process: the reachable-observer count for it can never exceed one, `required_distinct_successes: 2` is unreachable, and there is no refresh. Upstream `master` carries the identical lifecycle and 0.15.0 is the latest release, so there is nothing to wait for.

The crate's design goal is different from this repository's: it confirms an external address once for the Swarm's address book. This repository maintains a TTL'd, multi-witness verdict. Three facts bound the answer. Everything a separate client would reuse — the codec, the request and response types, the dial-back helpers, `Nonce` — is `pub(crate)`. A behaviour cannot be rebuilt inside a running Swarm: a fresh one has an empty `peer_info`, filled only by `ConnectionEstablished` events that have already fired, so it never learns that any peer is a server. And `deny.toml` forbids git dependencies, so a patched upstream cannot be depended on until it is released.

Two mechanisms already exist for what follows. `tools/checks/license_exempt.txt` is the recorded-provenance path CLAUDE.md §8 names for third-party material, deliberately empty until now. And a `[patch.crates-io]` entry with a `path` source resolves under `cargo-deny`'s sources policy, which bars registries and git and not paths — verified on 2026-09-09 against this workspace before this ADR was written.

## Decision

1. The workspace builds `libp2p-autonat` from `third_party/libp2p-autonat/`, the 0.15.0 crates.io tarball (sha256 `fab5e25c49a7d48dac83d95d8f3bac0a290d8a5df717012f6e34ce9886396c0b`), selected by a `[patch.crates-io]` entry in the root `Cargo.toml`. The version stays `0.15.0`, so advisory matching by name and version is unchanged.
2. The copy is the tarball minus its packaging files (`.cargo-ok`, `.cargo_vcs_info.json`, `Cargo.toml.orig`, `Cargo.lock`), plus the upstream `LICENSE` and one recorded diff, `INTERWEAVE.patch`. **Nothing else differs**, and the diff is the whole of what this repository owns in that tree.
3. The patch has two coupled halves and nothing else. `Behaviour::retest(&Multiaddr) -> bool` returns a known candidate to `Untested` and reports whether anything changed; it decides nothing about *when*. It resets a `Pending` candidate too, which is how the two stuck-`Pending` paths above are recovered. Because that orphans an in-flight nonce, the second half makes `reset_status_to` report whether a candidate still held the nonce and has the `AddressNotReachable` arm decline to emit when it did not — that arm is the only one which falls through to `GenerateEvent` rather than returning. **A probe `retest` abandons therefore produces no `Event` at all**, which is what lets a caller attribute every `Event` to the probe it last started.
4. Deciding when an address is re-tested — refresh while verified, a further observer until the threshold is met, retry after a failure under the dial gate's retry constants — is the `ReachabilityManager`'s (`crates/transport/runtime/src/reachability.rs`), keyed on the evidence `AUTONAT.md` §4 describes, and applied by the libp2p adapter calling `retest`. The crate's own tick and `with_max_candidates` remain its first-test sweep and its per-sweep ceiling.
5. Every file under `third_party/libp2p-autonat/` is listed in `tools/checks/license_exempt.txt` with licence, copyright holder, upstream version and tarball checksum. `third_party/README.md` carries the table of what is vendored and why. `LICENSE` is the one file the checksum does not cover, because the crates.io tarball does not carry one; it is fetched from the upstream repository and is excluded from `INTERWEAVE.patch` by name, so a byte-equality guard must special-case it.
7. `third_party/` is a landing zone alongside those ADR-0045 enumerates, and `README.md`, `IMPLEMENTATION.md` and `CLAUDE.md` §1 name it as one. Guards that walk first-party sources exclude it, on the same reasoning that excludes `spikes/`: a vendored dependency is evidence of nothing about this repository's own code and must never vouch for it.
6. The patch is dropped, and the `[patch.crates-io]` entry with it, when a crates.io release of `libp2p-autonat` carries an equivalent re-test path. Until then every libp2p version bump re-applies the diff to the new tarball and re-records the checksum.

## Alternatives considered

**Amending ADR-0035 to a single observer** was the cheapest and was rejected: the multi-observer rule is stated as a security property against one lying observer, and weakening it to fit a library inverts the source-of-truth order. It would also not restore refresh, leaving `verified_public` a fifteen-minute window after startup — which relay reservation targets and the connectivity summary are keyed on. **Writing an independent v2 client** would give full control of the lifecycle but, with the codec `pub(crate)`, means a second protobuf pipeline and roughly nine hundred lines of handler beside the server's copy of the same wire code, re-opening every question the crate already answers (nonce handling, amplification bounds, stream-upgrade errors) for a one-method defect. **Waiting for upstream** has nothing to wait for: `master` is identical and no newer release exists. **A git dependency on a patched fork** is barred by `deny.toml`, for the reasons that file records: no version, no yank mechanism, no advisory database. **Rebuilding the behaviour periodically** fails on `peer_info`, above. **Vendoring only the client module** fails on visibility: it would have to carry the protocol and generated code too, duplicating the server's wire code inside one binary.

## Consequences

The repository owns a 6,345-line tree it did not write, differing from its upstream by two coupled hunks and their comments, and the maintenance contract is the diff: reviewers audit `INTERWEAVE.patch`, not the tree. A libp2p version bump now includes re-vendoring the matching `libp2p-autonat` tarball and re-applying the patch, a step Dependabot cannot do and will not prompt for, since a path-patched crate is invisible to it; advisories still arrive through `cargo-deny`, which reads the lockfile by name and version. `ReachabilityManager` (`crates/transport/runtime/src/reachability.rs`, landing on PR #84) gains a scheduling role this ADR makes legitimate: an earlier draft of that module scheduled probes, and PR #84 removed it precisely because no lever existed. `retest` is the lever, at address granularity, with a completion event for every probe it starts. Server choice stays the crate's random pick among dialled connections, so a second distinct observer is probabilistic: with *n* dialled servers the chance that *k* consecutive probes land on one is *n*^-(k-1), and the manager counts distinct servers, so convergence is expected rather than guaranteed per probe. The spike harness at `spikes/spike-004/harness/` has its own workspace and is unaffected; its measurements describe upstream, which is what they should describe.

## Security implications

The property this exists to preserve is ADR-0035's: one observer cannot make an address `verified_public`. Under this decision the manager counts distinct servers, and a server cannot arrange to be counted twice because it does not choose itself — the crate draws the server at random from connections this profile dialled. The patch widens no attack surface reachable from the network: `retest` is called only by first-party code and reads only local state, and a late outcome for an orphaned nonce is refused on every path (a dial-back with an unknown nonce is rejected by `on_connection_handler_event`; `UnsupportedProtocol` and `Io` return without emitting; a success is dropped by the `received_dial_back` guard; and `AddressNotReachable` is declined by the patch's second half). **What the patch does remove is an absolute bound**: upstream probes each candidate at most once, so total probe volume over a process's life is capped by the candidate count. Under `retest` the bound becomes a rate — the crate's tick, `probe_interval`, times `max_candidates` per sweep (Decision 4) — and each probe costs an authorized server a dial-back and 30–100 kB. Nothing external can call `retest`, so this is a self-inflicted-load bound rather than an attack surface, and it is the manager's schedule that must respect `AUTONAT.md` §4's cadence. Supply-chain exposure changes shape rather than size: the vendored tree is pinned to a checksum recorded in two places and differs from the registry by an auditable diff, which is a stronger statement than a registry dependency makes; the cost is that the tree no longer moves with upstream security fixes until someone re-vendors, and the residual risk accepted is exactly that lag, bounded by the revisit conditions below.

## Operational implications

Nothing is configured. An operator observes `autonat_retests_total{reason}` — added to `AUTONAT.md` §9's required diagnostics by this decision, with reasons `refresh`, `second_observer` and `retry` — and a direct address reaching `verified_public` at all is the visible difference. If the patch were silently lost — a re-vendor that forgot it — the symptom is a profile that never leaves `unknown` or `not_verified` with servers answering correctly; `crates/transport/libp2p/tests/autonat_client_retest.rs` fails on that before it ships.

## Implementation implications

`third_party/` is a new top-level directory, a landing zone ADR-0045 did not enumerate and which this ADR adds with one rule: a subdirectory without a `license_exempt.txt` entry is an unreviewed import and fails `check_license_headers.sh`. The `[patch.crates-io]` table lives in the root `Cargo.toml` with a comment naming this ADR. The test for the method lives in `crates/transport/libp2p/tests/`, the lowest layer that can see both the vendored crate and the workspace's libp2p features; the vendored crate is not a workspace member, so its own test suite does not run here. Stage 11 step 3's adapter is where `retest` is first called, under the manager's three reasons; until then the method is built and tested and used by nothing, which `check_domain_fns_are_called.sh` does not govern (it is not a first-party domain function). Filing the patch upstream is part of this implementation, so the exit condition in Decision 6 can arrive. Two follow-ups are named rather than built here. A guard that asserts `third_party/libp2p-autonat/` equals the recorded tarball plus `INTERWEAVE.patch` needs the pristine tarball available to CI, and must special-case `LICENSE` per Decision 5. And a path dependency does not receive `--cap-lints=allow` as a registry crate does, so warnings from the vendored tree now reach this workspace's build output and a future toolchain can add more; today there are none, and the answer if that changes is a `[lints]` allow in the vendored manifest rather than edits to its source.

## Revisit conditions

Drop the patch when a crates.io `libp2p-autonat` release exposes a re-test path or a candidate lifecycle the manager can drive directly. Reopen this ADR if a libp2p major bump changes the v2 client's candidate model so the diff no longer applies cleanly; if `cargo-deny` or the repository's dependency policy changes to cover path patches; if ADR-0035's observer requirement is itself revisited; or if the probabilistic second observer measurably fails to converge on the real-NAT matrix SPIKE-004 phase B still owes — the measurement that would say so is the distribution of `autonat_retests_total{reason="second_observer"}` against servers dialled.
