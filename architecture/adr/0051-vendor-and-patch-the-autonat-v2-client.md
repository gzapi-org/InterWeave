# Vendor libp2p-autonat and give its v2 client a re-test entry point

**Status:** Accepted

## Context

ADR-0035 labels a direct address `verified_public` only on fresh evidence from **multiple distinct authorized AutoNAT v2 servers**, and states why: "reducing dependence on one lying/misconfigured observer". `architecture/transport/libp2p/AUTONAT.md` §5 adds that a verified state "must not survive beyond its evidence TTL without refresh". Both are accepted, both are security or liveness properties rather than tunings, and the standard-v1 client cannot deliver either.

The reason is the candidate lifecycle in `libp2p-autonat`'s v2 client, measured on 2026-09-09 by reading the crate rather than its documentation, and re-measured at 0.16.0 on 2026-09-19 when the `libp2p 0.57` bump vendored that release: every claim below held unchanged, and only the indices moved. Line numbers IN THIS SECTION cite the PRISTINE 0.16.0 release — the one the tree vendors — not the patched file in tree, whose later lines have moved again. A citation elsewhere in this ADR names the release it was taken against: a blanket claim of currency over text nobody re-derived is how an address that was merely old becomes one that is wrong. Its tick sweeps only candidates whose status is `Untested` (`v2/client/behaviour.rs:320`). Issuing a probe sets `Pending` and asks one randomly chosen dialled server (`:299`, `:339`). A received dial-back sets `Received` (`:165`); a server's "not reachable" sets `Failed` (`:231`). Only `UnsupportedProtocol` and `Io` go back to `Untested` (`:211`, `:222`). Re-reporting an address only raises its score — the entry is never removed and its status never changes (`:108-113`, the arm; the increment itself is `:112`). Two paths also leave a candidate `Pending` for ever with no event: a server reporting success when no dial-back arrived (`:191-197`), and a request dropped because the handler's ten-slot request map was full (`v2/client/handler/dial_request.rs:94-96` for the map, `:111-114` for the drop, still a silent `debug!`) — after the status was already set. The one public mutator, `validate_addr`, is `#[doc(hidden)]` and only *sets* `Received` (`:363-365`). **Once an address has been tested, no public path tests it again.** So an address is probed at most once, by one server, for the life of the process: the reachable-observer count for it can never exceed one, `required_distinct_successes: 2` is unreachable, and there is no refresh. 0.16.0, the release the tree vendors, carries the identical lifecycle, so there is still nothing to wait for; upstream `master` was read at 0.15.0's measurement and not re-read at the bump.

The crate's design goal is different from this repository's: it confirms an external address once for the Swarm's address book. This repository maintains a TTL'd, multi-witness verdict. Three facts bound the answer. Everything a separate client would reuse — the codec, the request and response types, the dial-back helpers, `Nonce` — is `pub(crate)`. A behaviour cannot be rebuilt inside a running Swarm: a fresh one has an empty `peer_info`, filled only by `ConnectionEstablished` events that have already fired, so it never learns that any peer is a server. And `deny.toml` forbids git dependencies, so a patched upstream cannot be depended on until it is released.

Two mechanisms already exist for what follows. `tools/checks/license_exempt.txt` is the recorded-provenance path CLAUDE.md §8 names for third-party material, deliberately empty until now. And a `[patch.crates-io]` entry with a `path` source resolves under `cargo-deny`'s sources policy, which bars registries and git and not paths — verified on 2026-09-09 against this workspace before this ADR was written.

## Decision

1. The workspace builds `libp2p-autonat` from `third_party/libp2p-autonat/`, the 0.16.0 crates.io tarball (sha256 `651fcbe0470d52db88ace805e94fd074aa18537312d43cbb531f761fa6916b43`), selected by a `[patch.crates-io]` entry in the root `Cargo.toml`. The version recorded here is the vendored tarball's exactly, re-recorded by Decision 8 on every bump, which is what lets Decision 7's guard ask the registry about the same release — not what lets `cargo-deny` see it, since it cannot (Consequences).
2. The copy is the tarball minus its packaging files (`.cargo_vcs_info.json`, `Cargo.toml.orig`, `Cargo.lock`; `.cargo-ok` is cargo's own extraction marker under `registry/src/` and is not in the tarball at all), plus the upstream `LICENSE` and one recorded diff, `INTERWEAVE.patch`, which carries every patch this repository holds against the crate — two once step 4's follow-up lands: the client's `retest` (Decision 3), and the server `Event` carrying its dial status (Decision 3a, whose recorded gap is the patch itself). **Nothing else differs**, and the diff is the whole of what this repository owns in that tree.
3. The first patch, `retest`, has two coupled halves and nothing else. `Behaviour::retest(&Multiaddr) -> bool` returns a known candidate to `Untested` and reports whether anything changed; it decides nothing about *when*. It resets a `Pending` candidate too, which is how the two stuck-`Pending` paths above are recovered. Because that orphans an in-flight nonce, the second half makes `reset_status_to` report whether a candidate still held the nonce and has the `AddressNotReachable` arm decline to emit when it did not — that arm is the only one which falls through to `GenerateEvent` *unguarded* — the success arm falls through too, behind its `received_dial_back` check. **A probe `retest` abandons therefore produces no `Event` at all**, which is what lets a caller attribute every `Event` to the probe it last started — with one precondition the caller owes, since `Event` carries no nonce: an outcome already queued in `pending_events` reaches the application on a later poll, so a `retest` between those two moments still delivers the stale one. Drain the behaviour's events before re-testing. That property rests on review of the recorded diff rather than on a check, and the reason is narrower than an earlier draft said. A probe in flight cannot be SYNTHESISED from outside: `handler` is a private module and `dial_request` is `pub(crate)`, so no test can inject `ToBehaviour::PeerHasServerSupport`, and without it the server pick returns `None`. It can be CAUSED: this crate also ships `v2::server::Behaviour`, reachable as `libp2p::autonat::v2::server`, so a two-Swarm test over real sockets — the shape `tests/connectivity/` already uses — would negotiate a genuine dial request and produce a real `Pending` candidate with a poll loop the test controls. **That test is owed in two halves.** A crate-level two-Swarm test on loopback — a raw `v2::client::Behaviour` fed a loopback candidate and dialled to a raw `v2::server::Behaviour`, which dials back whatever address the client requested (the vendored server carries no address-class filter and no configuration for one; `handler/dial_request.rs`) — negotiates a genuine dial request, reaches a genuine `Pending`, and proves the crate and the retest patch; it is written — `crates/transport/libp2p/tests/autonat_outcome_wire.rs`, on PR #90 (head a3c0e8c at the time of writing), where the first real outcome it produced exposed a classifier defect in step 3's adapter, so the test is that fix's proof — ahead of **step 4**, the step that constructs the server, whose record cites it. The substrate-level probe and dial-back, which `AUTONAT.md` §6 and `ScopedCandidates` refuse on loopback, need a public candidate and are SPIKE-004 phase B's. Step 3 (PR #89) tried the test at the substrate level and recorded in `crates/transport/libp2p/tests/autonat_client_retest.rs` and `tests/connectivity/tests/autonat_client.rs` why loopback cannot show it — a test that widened §6 to make the wire move would prove a lookalike. Saying the test was impossible would have told either step's author not to try.

   3a. The second patch makes the vendored server's public `Event` carry the dial status it already computed. The owner's external review pass (pinned at e4a11e17) and p2p-network-dev read, at f348095, that `crates/transport/libp2p/src/probe_server.rs:846` counts `served_ok` when the wrapper's decision is `Reached` and the crate's `Event.result` is `Ok` — and that in `v2/server/handler/dial_request.rs:244-250` (0.16.0) `Ok` means the response was sent and the stream closed, including a response whose `dial_status` is `E_DIAL_BACK_ERROR` after a failed nonce exchange (`:180-187`); the dial-back handler's `ToBehaviour` (`handler/dial_back.rs:131-134`) is `Ok(())` once the outcome went down the crate-internal back channel, whatever it was. The wrapper therefore cannot see the nonce result from any handler event, and a counter named `served_ok` can count a probe the requester was told failed. The fix is the patch, not a rename: the public server `Event` gains the dial status (the `DialResponse` status, or the enum the crate holds at `:180-187`) as an additive field — no existing field changed, the dial-back handler's channel contract untouched, so the hunk stays a pure addition and the next rebase pays for information, not for a reshaped channel. `served_ok` then counts `Reached` with a status of `OK`; a delivered negative is its own count in `AUTONAT.md` §9's table, and `AutonatProbeServed` carries the status. The handler-event shape (a `DialBackStatus` on `ToBehaviour`) was considered and declined: deeper into the crate for the same information. Implemented on `develop-qzapp/interweave/feat/relay-server-role` (open at the time of writing): c12ab47 adds the field and regenerates `INTERWEAVE.patch` against the 0.15.0 tarball — the release vendored then; f17fbbd regenerated it against 0.16.0 at the `libp2p 0.57` bump — with `third_party/README.md`'s row naming both patches; dad8a78 makes `served_ok` count `Reached` with status `OK`, counts a delivered negative as `served_failed`, carries `reached` and `succeeded` apart on `AutonatProbeServed`, and states the counters in `AUTONAT.md` §9, with a unit test pinning a delivered `E_DIAL_BACK_ERROR` as failed against an `OK` delivery. Recorded gap: the upstream filing beside the first patch's.

## Alternatives considered

**Amending ADR-0035 to a single observer** was the cheapest and was rejected: the multi-observer rule is stated as a security property against one lying observer, and weakening it to fit a library inverts the source-of-truth order. It would also not restore refresh, leaving `verified_public` a fifteen-minute window after startup — which relay reservation targets and the connectivity summary are keyed on. **Writing an independent v2 client** would give full control of the lifecycle but, with the codec `pub(crate)`, means a second protobuf pipeline and roughly nine hundred lines of handler beside the server's copy of the same wire code, re-opening every question the crate already answers (nonce handling, amplification bounds, stream-upgrade errors) for a one-method defect. **Waiting for upstream** has nothing to wait for: `master` is identical and no newer release exists. **A git dependency on a patched fork** is barred by `deny.toml`, for the reasons that file records: no version, no yank mechanism, no advisory database. **Rebuilding the behaviour periodically** fails on `peer_info`, above. **Vendoring only the client module** fails on visibility: it would have to carry the protocol and generated code too, duplicating the server's wire code inside one binary.

## Consequences

The repository owns a tree of some 6,400 lines it did not write, differing from its upstream by the first patch's two coupled halves in three hunks and, once step 4's follow-up lands, the second patch's additive `Event` field, and their comments, and the maintenance contract is the diff: reviewers audit `INTERWEAVE.patch`, not the tree. A libp2p version bump now includes re-vendoring the matching `libp2p-autonat` tarball and re-applying the patch, a step Dependabot cannot do and will not prompt for, since a path-patched crate is invisible to it. **`cargo-deny` cannot see it either**, which an earlier draft of this decision got wrong: a path-patched crate has no `source` and no `checksum` in `Cargo.lock` and the advisories check skips it. Measured with `atty 0.2.14`, which carries RUSTSEC-2021-0145 and RUSTSEC-2024-0375 — as an ordinary dependency `cargo deny check advisories` fails on both, and path-patched to a copy of the same source it prints `advisories ok`. So vendoring removes a crate from advisory coverage entirely unless something replaces it, which is why Decision 7 exists. `ReachabilityManager` (`crates/transport/runtime/src/reachability.rs`, landing on PR #84) gains a scheduling role this ADR makes legitimate: an earlier draft of that module scheduled probes, and PR #84 removed it precisely because no lever existed. `retest` is the lever, at address granularity. **IT DOES NOT COME WITH AN EVENT FOR EVERY PROBE, and the rule is a CONDITION rather than a list of outcome classes** — two earlier versions of this sentence tried to enumerate the classes and both were wrong, first by saying "every probe that COMPLETES" and then by naming `Ok` and `Err(AddressNotReachable)` as the emitting pair. An `Event` is pushed only when the outcome still owns its nonce AND, on the success arm, a dial-back was actually received. Every other path returns silently, including within both of those outcome classes: a server reporting success with no dial-back (`v2/client/behaviour.rs:186-198`) warns and returns, leaving the candidate `Pending` for ever so the tick never re-sweeps it; an `AddressNotReachable` whose nonce `retest` abandoned returns by the patch's own second half; and `UnsupportedProtocol` and `Io` reset the candidate to `Untested` and return. **`Behaviour::retest`'s doc comment enumerates the five paths that decline a LATE OUTCOME FOR AN ABANDONED NONCE, and is the one place that list is maintained — read it rather than any count here. It is not a list of every silent path**, which a review measured as the third wrong version of this sentence: the handler drops a dial request outright when its ten-slot request map is full (`v2/client/handler/dial_request.rs:99-113`), logs at debug, and leaves the candidate `Pending`, so no nonce is abandoned and no outcome is ever declined. The Context paragraph above names that one. What covers both scopes is the condition and the caller's timeout, not any enumeration. The caller's obligation follows from the condition and not from the list: reaching a verdict requires the caller's own timeout, because silence is indistinguishable from a probe still in flight. Review findings on PR #85. Server choice stays the crate's random pick among dialled connections, so a second distinct observer is probabilistic: with *n* dialled servers the chance that *k* consecutive probes land on one is *n*^-(k-1), and the manager counts distinct servers, so convergence is expected rather than guaranteed per probe. **One asymmetry `retest` exposes and does not close.** The client pushes `ToSwarm::ExternalAddrConfirmed` on a success (`v2/client/behaviour.rs:201-202`) and never emits `ExternalAddrExpired` — harmless upstream, where an address is tested once. Under `retest`, an address confirmed once and failing later stays in the Swarm's external-address set and so keeps being advertised by Identify, while this manager's own verdict expires on schedule. `AUTONAT.md` §5's "must not survive beyond its evidence TTL" therefore holds for the verdict and not for what the node advertises. Withdrawing the Swarm-level address is the adapter's to arrange in step 3, and is called out here because nothing in the crate will do it.

The spike harness at `spikes/spike-004/harness/` has its own workspace and is unaffected; its measurements describe upstream, which is what they should describe.

## Security implications

The property this exists to preserve is ADR-0035's: one observer cannot make an address `verified_public`. Under this decision the manager counts distinct servers, and a server cannot arrange to be counted twice because it does not choose itself — the crate draws the server at random from connections this profile dialled. The patch widens no attack surface reachable from the network: `retest` is called only by first-party code and reads only local state, and a late outcome for an orphaned nonce is refused on every path (a dial-back with an unknown nonce is rejected by `on_connection_handler_event`; `UnsupportedProtocol` and `Io` return without emitting; a success is dropped by the `received_dial_back` guard; and `AddressNotReachable` is declined by the patch's second half). The converse holds with one exception, recorded on the method: `validate_addr` — upstream's `#[doc(hidden)]` test-only hook, which nothing in production calls — also overwrites a nonce, and calling it on a pending candidate would swallow that probe's genuine failure. **What the patch does remove is an absolute bound**: upstream probes each candidate at most once PER COMPLETED VERDICT, so total probe volume over a process's life is the candidate count plus its transient-error retries — not an absolute cap, which an earlier version of this sentence claimed. `UnsupportedProtocol` and `Io` return a candidate to `Untested` and the tick sweeps `Untested`, so a transiently failing address is re-probed without limit even upstream. The Context paragraph's "once an address has been TESTED, no public path tests it again" is the precise version; this one had dropped the qualifier. Under `retest` the bound becomes a rate — the crate's tick, `probe_interval`, times `max_candidates` per sweep (Decision 4) — and each probe costs an authorized server a dial-back and 30–100 kB. Nothing external can call `retest`, so this is a self-inflicted-load bound rather than an attack surface, and it is the manager's schedule that must respect `AUTONAT.md` §4's cadence. Supply-chain exposure changes shape rather than size: the vendored tree is pinned to a checksum recorded in two places and differs from the registry by an auditable diff, which is a stronger statement than a registry dependency makes; the cost is that the tree no longer moves with upstream security fixes until someone re-vendors, and the residual risk accepted is exactly that lag, bounded by the revisit conditions below.

## Operational implications

Nothing is configured. An operator observes `autonat_retests_total{reason}` — added to `AUTONAT.md` §9's required diagnostics by this decision, with reasons `refresh`, `second_observer` and `retry` — and a direct address reaching `verified_public` at all is the visible difference. If the patch were silently lost — a re-vendor that forgot it — the symptom is a profile that never leaves `unknown` or `not_verified` with servers answering correctly; `crates/transport/libp2p/tests/autonat_client_retest.rs` fails on that before it ships.

## Implementation implications

`third_party/` is a new top-level directory, a landing zone ADR-0045 did not enumerate and which this ADR adds with one rule: a subdirectory without `license_exempt.txt` entries is an unreviewed import. For a Rust tree that rule is mechanical — the vendored `.rs` files carry no SPDX line, so every one of them fails `check_license_headers.sh` unexempted — but it is not self-enforcing for every shape: a vendored tree of only Markdown, TOML and `.proto` files would pass unexempted, because those extensions require no header. Vendoring one of those is where a reviewer, not a script, has to apply this rule. The `[patch.crates-io]` table lives in the root `Cargo.toml` with a comment naming this ADR. The test for the method lives in `crates/transport/libp2p/tests/`, the lowest layer that can see both the vendored crate and the workspace's libp2p features; the vendored crate is not a workspace member, so its own test suite does not run here. Stage 11 step 3's adapter is where `retest` is first called, under the manager's three reasons; until then the method is built and tested and used by nothing, which `check_domain_fns_are_called.sh` does not govern (it is not a first-party domain function). Filing the patch upstream is part of this implementation, so the exit condition in Decision 8 can arrive. One follow-up is named rather than built here: a guard that asserts `third_party/libp2p-autonat/` equals the recorded tarball MINUS its packaging files, plus the upstream `LICENSE` and `INTERWEAVE.patch` — Decision 2's list, which this sentence originally shortened to "the tarball plus `INTERWEAVE.patch`" and which a guard built from the short form would fail on four counts: the three packaging files it would expect and not find, and the `LICENSE` it would find and not expect. It needs the pristine tarball available to CI and must special-case `LICENSE` per Decision 5, so it is more than a grep — and until it exists, the tree's integrity rests on review of the recorded diff rather than on a check. And a path dependency does not receive `--cap-lints=allow` as a registry crate does, so warnings from the vendored tree now reach this workspace's build output and a future toolchain can add more; today there are none, and the answer if that changes is a `[lints]` allow in the vendored manifest rather than edits to its source.

## Revisit conditions

Drop the patch when a crates.io `libp2p-autonat` release exposes a re-test path or a candidate lifecycle the manager can drive directly. Reopen this ADR if a libp2p major bump changes the v2 client's candidate model so the diff no longer applies cleanly; if `cargo-deny` or the repository's dependency policy changes to cover path patches; if ADR-0035's observer requirement is itself revisited; or if the probabilistic second observer measurably fails to converge on the real-NAT matrix SPIKE-004 phase B still owes — the measurement that would say so is the distribution of `autonat_retests_total{reason="second_observer"}` against servers dialled.
