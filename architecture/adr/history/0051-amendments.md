# ADR-0051 — amendment history

Full amendment notes for [`0051-vendor-and-patch-the-autonat-v2-client.md`](../0051-vendor-and-patch-the-autonat-v2-client.md). The body reads current; this file records how it changed.

### Amendment 2026-09-18 — The owed two-Swarm test has two halves: crate-level at step 4, substrate-level at phase B

Decision 3 read: "That test is owed, and it belongs to the step that constructs these behaviours rather than to this decision, which constructs nothing." Stage 11 step 3 — the step that constructs the AutoNAT v2 client — landed as PR #89 (merge 530f4e0, 2026-09-18) without that test, so the sentence pointed at a step that was done. p2p-network-dev raised it over GZCoord the same day with the reason step 3 found: a probe needs a candidate, `AUTONAT.md` §6 refuses a loopback one and `ScopedCandidates` enforces that before the crate sees it, so on loopback the substrate's client never issues a dial request, and a test that widened §6 to make the wire move would prove a lookalike; the same suite does reach routes 2 and 3 over real sockets, so the limit is the candidate, not the harness. The one thing left unverified — whether the vendored server would dial back a non-global address — p2p-network-dev then read on PR #89: `Behaviour::new(rng)` is the server's only constructor taking any input (`Default` forwards to it with `OsRng`) and `handler/dial_request.rs` filters no address class, so it dials back whatever the client requested.

The decision therefore splits the owed test where the reachable candidate splits it. A **crate-level** two-Swarm test on loopback — a raw `v2::client::Behaviour` fed a loopback candidate and dialled to a raw `v2::server::Behaviour` — negotiates a genuine dial request and a genuine `Pending`, proving the crate and the retest patch. It turned out to be written already: `crates/transport/libp2p/tests/autonat_outcome_wire.rs` on PR #90 (head a3c0e8c at the time of writing; after three blind review rounds nothing outstanding at P1/P2 at that head — round one's P2 was fixed), where the first real outcome it produced exposed a classifier defect in step 3's merged adapter, so the test is that fix's proof; step 4, the step that constructs the server, cites it rather than owing it. The **substrate-level** probe and dial-back need a public candidate and remain SPIKE-004 phase B's, where the stage's closure already waits. Decision 3's body says so; the sentence about impossibility now speaks to either step's author.

### Amendment 2026-09-18 — Step 4 removed the four server look-alikes

The Decision 4 paragraph and its table were written for step 3's removal of the client's `max_inflight_probes` and `timeout`: an instruction that four server-side look-alikes — `AutonatServerConfig::timeout_ms` (held by a compile error and the fixed-length `check_ranges` tables), the `transport.connectivity.autonat.server.timeout` key in `config.schema.yaml` and the example profile (held by nothing in the deleting direction), and the `probe timeout: 15 seconds` row in `AUTONAT.md` §7 and the `probe timeout: **15 s**` row in `CONNECTIVITY.md` §6 (prose) — must survive that removal. Step 4, the step that constructs the server (PR #93, merge f21e8e75, 2026-09-18), removed all four: the pinned server bounds a dial request at 10 s and a dial-back stream at 10 s in code with no setter, and the dial-back's connection attempt is bounded by the Swarm's connection timeout, so the configured number described nothing — the same finding step 3 made for the client's `timeout`, which this decision already records. p2p-network-dev-01 raised it over GZCoord from #93's blind review (F5): the paragraph read as a present-tense claim about sites that no longer existed. The body now says the four were to survive step 3's removal and that step 4 removed them, keeps the table as the record of what held them, and points at `AUTONAT.md` §7's dated note for the reason. Nothing built is affected; no decision is re-made. The blind review of this amendment (PR #95) found the same defect one paragraph up — the client-key sentences still read present-tense although step 3 (PR #84, 02d1ac8) removed those keys — and in the implementation plan's step 4 entry (`architecture/roadmap/BOTTOM-UP-IMPLEMENTATION-PLAN.md`, which still said the field was a compile error to delete and counted 25 rows); both are folded here: the paragraph opens by dating both removals, and the plan reads 24 rows since step 4.
